Ondo puts perpetual execution in a single trusted enclave with multiple attestors

Event: On July 27, Ondo introduced Ondo Network with the live Ondo Perps as its first application. It said it would no longer implement the previously proposed Ondo Chain as a conventional Layer 1.

Mechanism: Matching, margin, risk checks and liquidation currently run privately inside a high-performance trusted execution environment. Several attestors approve code, share custody of critical keys and verify onchain events. Core state is recorded in a signed, replayable log.

Second-order effects: The design shifts assurance from public replication to software provenance, independent attestors, hardware attestation and log availability. A more open attestor set, onchain state commitments and external watchers were still future work.

ImplementationOndo Network and Ondo Perps were live, with execution still confined to a single enclave. The identities of attestors, volume, open interest, failover arrangements and public log-verification results were not disclosed.
